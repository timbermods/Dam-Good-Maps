# Integration proposals only

## Exact-weather follow-up

This follow-up proposes changes to current dev's `investigation/cycles/game-water.ts` and `game-soil.ts`. They remain copied prototypes in `weather/`; no reference or production file is edited. [WEATHER-PROOF.md](WEATHER-PROOF.md) supplies the invariants and [WEATHER-RESULTS.md](WEATHER-RESULTS.md) contains standalone and combined measurements.

[proposed-weather.patch](weather/proposed-weather.patch) gives the complete combined diff, including a minimal once-per-worker kernel loader and JS fallback. `weather-propose.ps1` generates it and checks applicability against isolated copies of current dev under `.work/`; it does not apply it to the repository's weather model. The loader/fallback adapter is an integration proposal, not an additional measured variant. Re-run the proof on the actual integrated adapter and selected cumulative subset. Use the patch as a combined reference, not a second patch over partially integrated steps.

1. Start with the descriptor changes in `weather/prototypes/soil-cache/game-soil.ts`: preserve initial/full-pass initialization; check still-wet tiles once; retain each tile's already-computed descriptors only after comparing all its old descriptors. Keep every soil float32 expression and the dirty-list first-add order unchanged. This is a small change with no new per-tile allocation.
2. Evaluate the scalar water kernel and `weather/prototypes/water-wasm/game-water.ts` as one separately gated step. Generate the kernel with `weather-wasm.mjs`, preserve its strict compiler configuration, and validate the emitted scalar FP instructions and binary hash. Compile the small module once when initializing a Weather worker, then pass that compiled module into each model's kernel adapter. The investigation bundler supplies `__waterWasm`; integration needs an explicit worker-owned module/factory instead of an implicit global. Retain the existing JS path as a fallback and for historical fidelity switches. Initialize all memory before creating views, make no per-tick copies, and never grow that memory while views are live.
3. Evaluate `weather/prototypes/water-sparse/game-water.ts`'s radius-two support independently before combining it with WASM. Preserve the active-state contract, negative-zero handling, dense fallback, and resetting of all required scratch buffers. For the WASM combination, use the support-aware contamination export after hydraulics, exactly as in `weather/prototypes/combined/game-water.ts`. Keep unsupported input modes on the reference path; do not treat arbitrary injected momentum/private-state edits as proved.
4. Treat `weather/prototypes/soil-saturation/game-soil.ts` as optional until its standalone results justify its 640 KiB per 256² instance. Recompute all affected counts before any affected saturation, retain the original local orders, and continue writing both alternating evaporation-buffer destinations at the reference times. The all-four combined result includes this candidate; a three-change combination has not been assigned its speedup.
5. Re-run the full map/daily-state proof and timing matrix after each cumulative integration step. Do not update expected hashes to accept a mismatch. Preserve the FIDELITY tick ordering, calendar, source and plant RNG streams, float32 soil rounding, and phase-boundary Measures calls. The continuous 73-day timeline is a different workload from the six independently reset probes; retain both tests.

Product scheduling and caching belong in the worker/view controller, after physics parity is established. Prioritize the existing independent Normal-drought probe only when the UI is showing that probe; a continuous journey must still simulate its preceding temperate days. Cache lossless outputs under the complete input/configuration/model-version hash, start work in the background after generation when resources permit, and yield/check cancellation between bounded tick batches. Do not advance the game clock from wall time or detach the model's live arrays to transfer a frame. Copy selected snapshot arrays for transfer. These proposals change availability and scheduling, not any simulated result.

The now-available terrain3d prototype already caches ordered column edges, uses separate overflow pressure, and transfers water sideways between overlapping gaps. Its contamination mix does not yet include exact-weather diffusion, and its evaporation scheduling differs. The support proof therefore needs the eventual layered model's actual passes; the present WASM kernel is not a drop-in replacement. Soil descriptors must cover per-run water selection and filled-cave/roof-thickness rules. Saturation invalidation must preserve column-overlap and slot-selection semantics. There is no sky/shelter evaporation term in the inspected rules. [STACKED-LAYERS.md](STACKED-LAYERS.md) gives the source-based assessment and integration conditions.

The earlier core/M9 proposals remain in [the original investigation](../simspeed/INTEGRATION.md). This follow-up changes only files under `investigation/simspeed-cycles/`.
