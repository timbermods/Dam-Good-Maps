# Designed-water prototype method

Everything is inside this investigation. Core and landscape dependencies are read-only. Core base: `84b1866b4e1d444346949a7dd57dc0f3f9f69ac5`. Remote dev `bf4e612` was checked for milestone changes; its validator still used same-level water. No merge or cherry-pick was performed.

## Reproduce

In this folder, with Node 24 and Microsoft Edge installed:

```text
npm ci
npm run build
npm test
npm run survey:water
npm run summarize:water
npm run serve
```

Open `http://127.0.0.1:4178`. The server serves static files only. Elevation is fetched directly by a module Worker with normal browser security. `LIMIT`, `OFFSET` (zero-based place index) and `SIZES` can restrict the survey. The full run uses no overrides. Do not run two surveys together. Raw experimental map files stay ignored under `.work/maps-water/`; passing examples are copied separately.

The immutable comparison is `results/`, [BASELINE.md](BASELINE.md) and [METHODS-BASELINE.md](METHODS-BASELINE.md), generated by commit `c9874e2`. Reproducing that algorithm requires that commit; running the new worker with the old runner is not the baseline. Do not rerun `adapt.mjs`, which mechanically generates the old converter.

## Terrain and water

Sampling, bilinear Terrarium decoding, projection and monotonic 1–16 height mapping retain the baseline method. Cheap scale previews compare 30/60/120 m/tile. Missing drainage no longer subtracts 20 points or vetoes a place. Low relief, extreme slopes and the explicitly uncertain sea/low-ground proxy still inform the scale ranking. No native-water mask is required. Mapping is never followed by a terrain edit.

`designWater` uses priority-flood routing on real elevations, including a 16-cell halo, and another routing pass on quantised terrain to measure natural basins. Priority flood supplies routes only; it never fills exported ground. Extract channels at accumulation `max(24, area*0.003)`. A spring candidate must be a channel's first cell, with no incoming channel and higher neighbouring terrain. An entering river gets its source on the exact edge cell crossed by its upstream halo channel. Midstream cells are ineligible, however attractive their downstream ground. Sources inside filled basins are ineligible too. Each selected tributary has its own head.

Rank those eligible origins by nearby flat banks, confined valleys, downstream drops, natural basins and route length. Downstream interest propagates upstream with a 0.965 discount. The heuristic does not inspect a place name or family. It favours origins whose water will cross interesting ground, never adds a source inside that ground to boost an existing river.

The first design chooses up to 1/1/3 separate tributary heads at 96/128/256. The alternate starts eight percent further down the ranked candidates and uses one head at lower flow. Per-head strengths are `3*sqrt(size/128)` and `1.8*sqrt(size/128)`. These are game settings, not measured discharges. To increase a river's flow, increase its head strength; this prototype does not implement source clusters and never uses downstream boosters. If no natural head/entry candidate exists, introduce a designed river at the boundary, including below sea level. A flat plain may lack a pumpable bank; that is a start failure, not a missing-native-river failure.

Canonical prefill rejects proposed heads on another tributary's possible wet route. Before accepting a multi-head map, independently run canonical settling with each source's own flow off, retaining its footprint. Its head must stay dry (depth ≤0.05) with the other tributaries flowing and settled. This stricter local origin audit is recorded separately. A single-source plan trivially has no other stream. Failed openings skip this expensive acceptance audit and remain unavailable for download. These are checks of the designed game rivers/lakes; a DEM alone cannot identify every native real-world river or lake surface.

The optional `balanced`, `waterfall` and `basin` intentions change feature weights. They bias where water is introduced, never carve a cliff, channel or lake. No natural-language or exact-point intention parser is implemented. The actual water comes entirely from the existing canonical prefill/settle, with its normal four-day cap. Settling remains required, and draining is allowed.

## Start and local checks

The converter searches at most 48 existing flat 3×3 sites, with a dry ring and an entrance. It ranks clean pumpable water within 20 walking tiles first, then reachable moist land. Natural Slope entities connect existing one-level steps with dry approaches. The local D153 check uses the actual exported links and shared object blockers. This follow-up also blocks flooded cells during start selection and the water walk, so a path cannot cross a flooded river to reach its far bank. The baseline did not block those cells; the difference makes the comparison conservative in that respect.

Resources still use the existing moisture-aware converter and base thresholds. `LOCAL D151–D153 adapter` remains explicitly named in every result. It changes only the old water-distance/coverage/body-size/outflow policies; other base load, design, resource and canonical-settle failures remain blocking. It still uses the old Normal 40-living-tree threshold; do not invent D164 log defaults ahead of the milestone. The stricter dry-path regression, slope-only walk, blocker and contamination tests guard the temporary adapter.

## Bounded automatic search

Each configuration tests up to two source designs, stopping if one passes. If the requested configuration fails, test the other two scales, the other two sizes at the original scale, and two opposite nearby offsets. A coarse drainage cell determines the offset; without one, use half the original window north/south. Clamp latitude and wrap longitude. The search has at most seven configurations and fourteen water designs, plus origin-audit simulations for otherwise passing multi-head designs. Cache bytes across attempts. A terminated worker cancels the whole search immediately.

Among tested results, passing beats failing; otherwise fewer failed checks, settling, moist opening area and shorter water walk rank results. Stop at the first passing design in the prescribed order. This favours the requested place/size and is not an exhaustive optimum search. A passing returned map always discloses its actual coordinates, size and scale. Exhaustion returns the best failed preview plus the two tested nearby previews, each with reasons; download stays disabled. Fetch failures are recorded as failed attempts and never replaced by made-up terrain.

## Fair comparison and limits

The same fixed `places.json` supplies 150 requested place/size pairs. Reports distinguish first source design, best of up to two designs in the requested area, and final result after automatic search. A recovered 96² request may return 256² or a nearby area; it counts only in the recovered column. Per-place counts mean any of that place's three requests passes. They are not 50 random samples of Earth.

Every attempt and its location/scale/flow/failures is recorded. `directMs` includes screening, fetch and requested-area designs; `retryMs` covers the remaining search and final analysis; total includes export/reload. Added seconds are paired against the saved original time for each request. Browser cache, network and host workload are not controlled, so speed comparisons are indicative. The page heartbeat continues during work. Focused tests and one brief browser test overlapped part of the matrix, so timings include that host load. The ten before/after places were fixed before results: Grand Canyon, Mississippi, Crater Lake, Fuji, Geiranger, Yosemite, Victoria Falls, Kansas, Dutch polder and Sahara, all requested at 128². Captions reveal changed settings.

All selected exports are written, read and load-validated. Only passing examples and UI downloads are offered as maps. Full provider notices are embedded in the description and `ATTRIBUTION.txt`; coordinates, modified-data wording, source hashes and complete attempts live in `pickplace.json`. Timings/date diagnostics mean the ZIP is not byte-stable. No in-game checks were run and no game was launched.

Known limits persist: ±85° coverage, untested Firefox/Safari/mobile performance, very flat landscapes, the verified Taveuni upstream zero-tile seam, sea level being an unreliable water mask, and DEMs having no lake-bottom depth. Designed water removes the need for a native river; it does not repair poor elevation data or prove a fun drought opening.
